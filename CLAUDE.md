# Commander

`cmdr` tracks the user's Archidekt Commander decks (user `MAKKIS`) in `decks/` and supports research on upgrades,
EUR prices and brackets. The README covers usage; this file covers working on it.

## Commands (from the repo root)
- Full check, the same as CI would run: `uv run ruff check && uv run ruff format --check && pyright && uv run pytest`
- Pull decks and refresh card data: `uv run cmdr sync` (config is in `%APPDATA%\Commander\config.toml`, workspace `D:\Projects\Commander\decks`, card database `%LOCALAPPDATA%\Commander\cards.sqlite`). It also compiles each deck's Considered ideas from the meta and recent Archidekt decks (ADR 0014), so the first sync of the day takes minutes: run it in the background, or pass `--no-ideas`. Tests that sync only as setup pass `--no-ideas` too
- Research: `uv run cmdr analyze <deck> --details`, `uv run cmdr price <deck>`, `uv run cmdr bracket <deck> --details`, `uv run cmdr suggest <deck>`, `uv run cmdr card "<name>" ...` (rules text and Tagger tags) and `uv run cmdr tags <text>`; set `PYTHONIOENCODING=utf-8` when piping output from Git Bash, because deck names contain emoji
- cEDH meta for the bracket 5 decks: `uv run cmdr meta` (all side by side) or `uv run cmdr meta <deck>`; the first run of the day takes minutes because EDHTop16, Archidekt search and Spellbook are paced (ADR 0007), so run it in the background and read the output file
- Catch up on what the user decided in the app before deck work: `uv run cmdr board log --since <last time>`
- Put research on a board: `uv run cmdr board add <deck> "<card>" --by claude --reason "..." --replace "<deck card>=<why>"`, or `board research` for a card already there; the decision is the user's
- Cards still to buy: `uv run cmdr toget [deck]`; `uv run cmdr toget <deck> "<card>" --ordered|--arrived` writes the label to Archidekt at once (ADR 0010), so only on the user's say-so
- Change a deck: `uv run cmdr apply <plan.toml>` previews; `--save` writes to Archidekt and needs `uv run cmdr login` once (the user types the password; never ask for it or pass it on a command line)
- Desktop app: `uv run cmdr app`; its log is `%LOCALAPPDATA%\Commander\logs\commander.log` (`CMDR_LOG_LEVEL=DEBUG` logs every bridge call). Build the exe: `uv run --group build pyinstaller --noconfirm --clean --onefile --windowed --name Commander --icon src/commander/web/commander.ico --add-data "src/commander/web;commander/web" src/commander/app_main.py` (lands in `dist/`)

## Conventions
- Signing in to the app as another account switches the config's `user` and `workspace` to that account's folder (ADR 0023), and the CLI follows; before deck work, check that `uv run cmdr list` shows the user's decks from `decks/`.
- Decks are named by their commander's short name ("Ellivere", "Pantlaza"), as the user does; `Deck.short_name` gives it.
- Each `decks/<id>-<slug>/` holds `deck.json` and `list.md`, which `sync` regenerates; `notes.md` and `profile.toml`, which belong to the user; and `board.json` and `activity.jsonl`, which only `cmdr board`, the app, `suggest --to-board` and `sync` write. Research findings go in `notes.md` or on the board; never hand-edit the generated or board files.
- Commit deck syncs and board changes separately from code changes, with a subject like `Sync decks: <what changed>`, so the deck history stays readable.
- Sideboard and Maybeboard cards (outside the deck) mean "considering" (ADR 0006): sync puts them on the board, board cuts move to the Maybeboard, and turned-down ones are dropped on the next save.
- Archidekt's API is undocumented: every response from it, and from Scryfall and Commander Spellbook, goes through `jsonshape` validation, and each service sits behind its own module. EDHREC is never fetched: its terms forbid automated requests (ADR 0003); its popularity rank comes inside Scryfall's bulk data. Check a new data source's terms before fetching from it.
- Test fixtures are trimmed real responses (`tests/fixtures/`), and expected values are hand-derived from them. `scryfall_cards.jsonl` holds real bulk lines for the fixture deck's cards, with their real oracle text and keywords; `scryfall_tags.jsonl` is hand-built on real role-tag UUIDs. The bulk readers refuse files under 10,000 cards, so `conftest.py` pads the fixtures with generated filler. `spellbook_estimate.json` and `spellbook_combos.json` are trimmed real `estimate-bracket` and `find-my-combos` answers. The role taggings of the suggested cards (Arcane Signet, Chaos Warp and so on) are made up in `conftest.EXTRA_TAGGINGS`, and `test_scryfall` reads the real tag lines alone. Tests that run `bracket` or `suggest` copy the card database into their own cache folder (`own_cache`), because cached Spellbook answers would otherwise leak between tests. A sync of the fixture deck puts its two Maybeboard cards on its board, so board tests that want an empty board delete `board.json` and `activity.jsonl` after syncing.
- Never commit `cmdr meta` output or EDHTop16 statistics (into `notes.md` either): EDHTop16's terms forbid redistributing them. Name a finding and its source ("Sylvan Safekeeper is in most top-cut Ellivere lists") rather than pasting its tables.
- `apply --save` and board saves change the user's real decks on Archidekt (ADR 0004). Try changes to them on the private test deck 27461808 first, never on a tracked deck. The login token lives in Windows Credential Manager (service `Commander (cmdr) Archidekt`); `conftest.memory_keyring` swaps in an in-memory keyring for every test, and `FakeArchidekt` implements the login, card lookup, snapshot and `modifyCards` calls, categories included.
- Card roles map to Tagger tag UUIDs in `scryfall.ROLE_TAGS`, and board wipes are narrowed by `_CREATURE_REMOVAL`/`_NONCREATURE_REMOVAL` (ADR 0020); a change to either, or to the database tables, needs `carddb.SCHEMA_VERSION` bumped so old databases get rebuilt.
- The app page (`src/commander/web`) builds DOM nodes with `textContent` only, never `innerHTML`, because board text comes from people and Claude; `test_desk` checks every script for `.innerHTML` and the like. The page is one classic script per area, inlined in the order `index.html` lists them; run `for f in src/commander/web/*.js; do node --check "$f"; done` after editing them (Node is only a syntax checker here, not a dependency).
- pyright runs in strict mode over `tests/` too; read bridge answers in tests through typed helpers (`test_desk.items`) rather than `type: ignore`.
